- Linked feature IDs and decision IDs: new F-031 (Ledger Analysis); F-008 (Tally extraction, VERA Tools path replaced); F-029 CAAT Tools overlaps in part. Decision: remove Tally Tools and accept the loss of Opening Balance Matching (owner, 13 and 14 November 2026).
- Current behaviour and code evidence (before): VERA Tools had a "Tally Tools" tab (`TallyTools` in `src/pages/AuditTools.tsx`, ODBC via `src/hooks/useTallyODBC.ts`, `src/hooks/useOpeningBalanceMatching.ts`). "Daybook Export" and "Duplicate Transaction Finder" were "Coming Soon" cards.
- Intended user outcome: load a company's data from live Tally (or Day Book Extractor, Busy, Zoho, Excel files) and run the ledger-analysis checks of the owner's scope note in one screen, with Excel exports. Details in [LEDGER_ANALYSIS.md](../LEDGER_ANALYSIS.md).
- In scope: the Ledger Analysis module and tab; read-only Tally HTTP XML fetch in the main process; checks (trial balance, day book vs TB, dormant and unchanged-balance ledgers, negative ledgers, incomplete masters, unusual balances incl. creditors with several expense heads, round-off check and Details panels, standard deviation, duplicates, unusual entries); exports; removal of Tally Tools. Out of scope: saving results to the engagement, working papers or Review Notes; Opening Balance Matching; removing the now-unused ODBC IPC handlers; fixing the pre-existing T-003 test race.
- Binding constraints and open questions: nothing is written to Tally; data stays in renderer memory; signs debit-positive internally; Tally's own closing balances are not altered. Open: which of Ledger Analysis / CAAT Tools is canonical for overlapping analytics; whether to persist results; whether to remove the unused ODBC handlers.
- Inputs, fields, types, units, defaults and validation: host/port (default `localhost:9000`), optional company, period (defaults to the engagement's financial year), day book method (Auto). Check limits in Settings (rupees; not persisted): small balance ₹1,000; outlier 2 SD; near-duplicate 7 days; 2 expense heads; similarity 0.90; tolerance ₹1; round amount ₹10,000 / multiple of ₹1,000; repeated amount 3 vouchers from ₹5,000; 40A(3) ₹10,000; 269ST ₹2,00,000; 269SS/269T ₹20,000; round-off entry ₹10.
- Source data and provenance: live Tally export (ledger, group, voucher-type masters; vouchers month by month) or user-chosen files. Warnings list what was left out (optional, cancelled, post-dated, non-accounting voucher types) and any month that could not be fetched.
- Business rules, signs, rounding and statutory versions: see the Checks table in LEDGER_ANALYSIS.md. The cash checks state s.40A(3), 269ST, 269SS/269T thresholds as analysis aids, not legal determinations; the ₹35,000 goods-carriage limit and Rule 6DD exceptions are stated, not computed.
- Roles, assignments, permissions and lock rules: both IPC handlers require a signed-in user (any role) and are read-only; there is no engagement-level data because nothing is stored. VERA Tools still requires a selected engagement in the screen.
- States and allowed transitions: no persisted state. Round off is counted in the creditor check until the user chooses "Ignore round off in this check"; this choice is per screen session.
- Tables, files, localStorage and migration impact: none. No schema change, no migration.
- Read and write path: `LedgerAnalysisTool.tsx` → `tallyClient.ts` → `window.electronAPI.ledgerAnalysis` (`electron/preload.cjs`) → `ledger-analysis:tally-companies` / `ledger-analysis:tally-fetch` (`electron/main.cjs`, sign-in check) → `electron/ledger-analysis/tally-xml.cjs` → Tally HTTP server. Files are parsed in the renderer.
- Outputs, preview and export effects: on-screen tables; Excel per table, "Export all findings", Details exports, three day book layouts. Files are written through the browser download path only.
- Error, cancellation, retry and duplicate behaviour: connection refused / timeout messages name the port and the Tally setting; a month that times out is retried once, then named MISSING. A second Fetch click starts a new fetch.
- Acceptance scenarios: day book vs TB agrees for every ledger on a live company (done: 767/767 on the owner's test company); dormant / unchanged split matches the owner's definition; non-accounting vouchers left out; signed-out IPC calls refused; old `?tab=tally` links open Ledger Analysis; GST, MCA, Income Tax, PDF and Analytics tabs unaffected; owner UAT.
- Validation commands and required environment: `npx vitest run src/modules/ledger-analysis`; `npx tsc -p tsconfig.app.json --noEmit` (no diagnostics in changed files); `npx eslint` on changed files; `npm run build`; `npm run test:t003-authorization`; `npm run docs:inventory`; `npm run docs:check`. Live checks need TallyPrime with the company open and its server on.
